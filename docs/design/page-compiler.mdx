# Page compiler

The page compiler turns an MDX page into a JavaScript module that the web app can show, and records what the page contains. This page follows a page through its stages, then covers the list of pages, replies, and builds.

## Pipeline

The page compiler is [a list of Vite plugins](/-/files/yapparatus/src/compiler/pipeline.ts) in `src/compiler/`. Its core is the MDX plugin, [set up with the stages in order](/-/files/yapparatus/src/compiler/page.ts#L29-L47); the others add icons, styles, and React, and [virtual modules](/-/files/yapparatus/src/compiler/virtual-modules.ts) give the web app the document. The `yapparatus()` plugin in [`src/vite/plugin.ts`](/-/files/yapparatus/src/vite/plugin.ts) combines these plugins with the [server](server) and with what only a build needs. Each stage reads or changes the page's syntax tree, which holds its headings, paragraphs, and components. <Ref to="compiler-pipeline" /> shows the stages in order.

Files are read before the outline is recorded, because the page's [revision](#revisions) covers those files. Highlighting runs after the excerpts and the source marks, so it colors every code block and numbers its lines.

On the dev server, the diagnostic store, the pictures, and the document module compile a page [in the server's own environment](/-/files/yapparatus/src/compiler/page.ts#L45-L60), so these compiles do not hold back the browser's first page load. A page whose file changed since its last compile is compiled again.

A stage that finds a problem adds an issue for the file. After each compile, the server turns the issues into diagnostics at the page's lines, as [origins](diagnostics#origins) describes. A stage that cannot continue throws, and the compile fails with `COMPILE_FAILED`. <Ref to="compiler-sample" /> shows a page and its module.

## The document module

The web app reads the list of pages from one module, which the compiler [writes from `document.json` and the page files](/-/files/yapparatus/src/compiler/virtual-modules.ts#L170-L263). <Ref to="compiler-document-module" /> shows what it holds.

The compiler first checks `document.json` and its page list against the files on disk, and reports errors as `PAGE_LIST`.

The module holds every page's outline, so the contents, figure numbers, and `<Ref>` work before any page's code loads. To get the outlines, the compiler compiles every page. A page that fails to compile gets an empty outline, so the contents still list it.

A page's code loads when the page is first shown. When it changes, the module swaps in the new page module and outline and tells the web app, as [hot updates](web-app#hot-updates) describes. Pages are compiled without React Fast Refresh, which would reload the browser for a module that exports an outline.

## Markdown conventions

The conventions stage reads Markdown forms and component children and writes what it finds into props, so each component receives plain data. <Ref to="compiler-conventions" /> lists them.

<Table id="compiler-conventions" caption="What the conventions stage reads, what it makes, and the codes it reports.">

| Written | Becomes | Codes |
|---|---|---|
| A blockquote that starts with `[!NOTE]` or another kind | An alert | `ALERT_TYPE` |
| A Markdown list in `<FileTree>` | The tree's entries | `FILE_TREE_INVALID` |
| `<Panel>`s in `<Tabs>` or `<Columns>` | The labels | `PANEL_CONTENT`, `PANEL_LABEL`, `PANEL_NESTED`, `TOO_MANY_COLUMNS` |
| `<Columns>` in a `Figure` or `Listing` | A wide figure | |
| A numbered figure in a `Figure` | Nothing | `FIGURE_NESTED` |
| A fenced code block | A checked language | `CODE_LANGUAGE` |
| A `####` heading or deeper | Nothing | `HEADING_DEPTH` |

</Table>

Code marks, such as `// [!code ++]`, are removed before highlighting, so they work in any language, including JSON.

## Math

`remark-math` reads TeX between `$$` marks, inline in a sentence or as a block on lines of its own. A single `$` stays text, so a price needs no escaping. The math stage runs first among the HTML stages and turns each formula into MathML with [Temml](https://temml.org/), so the browser draws it natively and the page loads no math code or style sheet. The web app draws math in a [math font the system has](styling#typography-and-scales). MathML takes the text color of the theme and prints as it is. TeX that does not parse is `MATH_INVALID` at its line, and the page shows the TeX as code.

## Icons

For each `<Icon name="collection:name">`, the icon stage imports that one icon, and a Vite plugin turns the import into an SVG component, so a page bundles only the icons it names. The icons come from the installed icon packages and the project's `icons/` directory. A name that is not a literal string cannot become an import, so the page fails with `COMPILE_FAILED`.

## Diagrams

The diagram stage runs each draw program in [a fresh JavaScript context](/-/files/yapparatus/src/compiler/stages/diagrams.ts#L201-L238) without Node's names or the page's, and hands the result and the steps to the [diagram compiler](diagram-compiler). The context keeps names out but is not a sandbox. A program that throws is `DRAW_FAILED` at the page's line.

The compiled diagram replaces the draw program, so the browser receives only data, and its diagnostics become issues of the page. Compiled diagrams are cached by their source, so an edit elsewhere on the page does not compile them again.

## Charts

The chart stage reads and checks each chart's data. Data written on the page goes into the page. Data from a file is loaded separately, and an edit to the file compiles the page again. See [charts](charts#data-sources).

## Code and excerpts

Code blocks, excerpts, and the [file view](web-app#file-view) share [one highlighting function](/-/files/yapparatus/src/compiler/stages/highlight.ts#L29-L74), which uses the Shiki highlighter with the theme's colors. <Ref to="compiler-highlighted-code" /> shows its result: each token style once, and each line as pairs of a style and a text.

For each `<Excerpt>`, the excerpt stage reads the file named in `from`, by the rules in [external files](documents#external-files), and finds the lines:

1. The first line is the only line that contains the `start` text. No match or several are an `EXCERPT_TEXT` error.
2. With `end`, the last line is the next line that contains the `end` text.
3. Without `end`, the excerpt runs to the end of the block that the first line opens, by indentation.

The stage adds a code block with those lines, numbered as in the file, and the bar above it links to them. A file that cannot be read leaves the excerpt empty and is reported as `BROKEN_LINK`.

Two headings or numbered items with the same id are `DUPLICATE_ID`. A page must have exactly one `#` heading.

The source marks stage marks every top-level block, list item, and table row with its file and lines. The web app reads these marks to turn a selection into references, as [commenting on the page](web-app#commenting-on-the-page) describes.

## Revisions

A page's revision is a hash of the page's text and of every file it reads for excerpts and charts. The outline stage writes it into the outline. The diagnostic store computes it again from the files on disk, as [revisions and reports](diagnostics#revisions-and-reports) describes. A change to a component's code does not change a revision.

## Replies

The server compiles each reply from the agent with the same page compiler before it accepts it, so a reply's diagrams and excerpts get the checks of a page. [Reply checks](server#reply-checks) describes the rest.

A build finds the external files by their addresses in the text of its pages, and stores each one highlighted for the file view.

## Design decisions

**Diagrams are compiled with the page.** Compiling in the server finds a diagram's problems on every save without a browser, lets the server refuse a reply with a broken diagram, and keeps the diagram compiler out of the reader's download. The cost is that a draw program cannot use the page's imports.

**Excerpts find their lines by text.** Line numbers show the wrong code after lines are added above, and marker comments, as in [mdBook](https://rust-lang.github.io/mdBook/format/mdbook.html#including-portions-of-a-file), change the file. Quoted text, as in the `start-after` option of [Sphinx](https://www.sphinx-doc.org/en/master/usage/restructuredtext/directives.html#directive-literalinclude), fails with an error at the page's line when the file changes.
