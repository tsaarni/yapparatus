# Overview

This document describes how Yapparatus works, for the people and agents who change its code. To write a document with Yapparatus, read [the authoring guide](/-/files/yapparatus/starter/docs/guide.md).

## What Yapparatus does

Yapparatus lets a person and their coding agent write and revise a technical document together. The agent writes the pages. The person, called the reader, reads them in the browser, selects something on a page, and comments on it in a message to the agent. A message can be a question, a correction, or a request to change the page. The agent revises the page, replies in the chat beside the page, or both. The agent is the reader's own coding agent, running in a terminal.

Three properties make this work. First, the agent can write a rich document with little effort. It writes short MDX pages, and Yapparatus lays them out and draws their diagrams, charts, and code excerpts. Yapparatus reports every error with its file and line, so the agent fixes its own pages. Second, everything on a page has an address: a sentence, a table row, a shape in a diagram, or a few lines of a source file. The reader can point at exactly what a comment is about. Third, the page is live. An edit by the agent appears while the reader reads.

People use Yapparatus for:

- Understanding a codebase. The agent explains unfamiliar code with diagrams and excerpts of the real files, and the reader comments where something is unclear.
- Design documents. The reader directs, and the agent writes and redraws.
- Reviewing a plan or a change. The agent explains what it intends to do or what it did, and the reader marks what to change.
- Reports, such as benchmarks, incident analyses, and comparisons, with charts drawn from the data files that a tool produced.
- Teaching material about protocols, data layouts, and algorithms, with diagrams that the reader steps through.

A finished document can be built as a static website or as one HTML file, without the chat.

The [web app](web-app) is a React app that shows the pages and the chat panel. The [server](server) is a Vite dev server that the `yap` command starts for one [document directory](documents). Its [page compiler](page-compiler) compiles the pages with their [diagrams](diagram-compiler) and [charts](charts), and its [REST API](rest-api) keeps the chat and the [diagnostics](diagnostics). The agent calls the [agent library](agent-library) from shell commands, and everything it reads is text that the server writes.
