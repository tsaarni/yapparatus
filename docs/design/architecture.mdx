# Architecture

Yapparatus has two programs: the reader app, which runs in the browser, and a dev server. Both use the same project directory. The reader's agent runs in a terminal beside them. This page describes how a project is created, what the browser, the server, and the agent each do, how they communicate, and where their code is.

## Creating a document

A new document starts as a copy of the [`starter/`](/-/files/yapparatus/starter/README.md) template:

1. The reader copies `starter/` to a new directory and installs its dependencies. The starter is a document with one page that says it is empty.
2. The reader starts the dev server with `pnpm dev content`. The server prints an address, and the reader opens it. The browser shows the empty document.
3. The reader chooses **Ask** to open the chat. No agent is connected yet, so the chat offers a **Copy prompt** button.
4. The reader starts a coding agent in the project directory and pastes the prompt into it. The prompt tells the agent how to connect to the chat.
5. The reader asks in the chat for a document on some topic. The agent writes the pages in `content/`, and the browser shows them as they change. From here on, the [reading loop](overview#purpose) runs.

## Document directories

A project can hold several documents. Each one is a document directory: a directory with its own `document.json` and pages, such as `content/` in the starter or `docs/design/` in this repository. The project's `icons/`, `docs/`, and dependencies are shared.

1. **The server runs one document at a time,** given as a path relative to the project directory: `pnpm dev docs/design`. The `yap` command in [`src/cli.ts`](/-/files/yapparatus/src/cli.ts) takes the path and passes it to the Vite plugin, like `vitepress dev docs` for VitePress. A Vite script cannot take the path, because `vite <path>` reads the path as Vite's root. The command has no default document, so the command line always names the document.
2. **The command loads the project's `vite.config.ts` when it exists.** A project can therefore add Vite options and plugins. The command adds `yapparatus()` itself, and the plugin refuses to run twice. The server listens only on `127.0.0.1`. The command has no option to change this address, because the chat server trusts every process that can reach it. See [the library implementation](chat#library-implementation).
3. **Every output mirrors the document's path.** The chat is in `.yapparatus/<directory>/`, the website build in `dist/<directory>/`, and the single file in `dist-single/<directory>/index.html`. A document's chat and builds therefore stay separate from those of other documents.
4. **A document directory cannot contain another one.** The pages are every MDX file under the directory, and the chat state mirrors the path. A document in `docs/` would take the pages of `docs/design/` as its own. The server therefore refuses to start and names both directories.
5. **The project has one `.yapparatus/server.json`.** The newest dev server writes it. The `yapparatus/agent` library reads this file to find the running document. The snippets (short TypeScript programs that the agent runs) therefore do not name a document.

## Communication

The programs communicate through HTTP messages and through files in the project directory.

**The server API has three resources, `chat`, `diagnostics`, and `files`, under `/-/api`.** Each is named after a part of the document. The browser and the agent use the same resources. A request names what it needs in parameters. The server sends changes to the browser on Vite's hot-update connection. [The server API](api) describes every request, its parameters and JSON bodies, and the updates.

### Agent library

[`src/agent.ts`](/-/files/yapparatus/src/agent.ts) is the package's `yapparatus/agent` export. It provides the functions `waitForMessage()`, `sendReply()`, and `checkDocument()`. The agent calls them from snippets. The library runs in the agent's Node process and finds the server through `.yapparatus/server.json`. It prints only the text that the server writes. [Waiting for messages](chat#waiting-for-messages) describes the library's behavior.

### Logging

[`src/logger.ts`](/-/files/yapparatus/src/logger.ts) is the logger for the dev server, the browser, and the `yapparatus/agent` library. `createLogger("chat")` returns the functions `debug`, `info`, `warn`, and `error`. Each line they write is tagged `[yapparatus:chat]`.

1. **`YAPPARATUS_LOG` sets the log level everywhere.** The levels are `debug`, `info`, `warn` (the default), `error`, and `silent`. Node reads the setting from the environment. The plugin passes the value to the browser through Vite's `define` option, so the browser logs at the same level as the server.
2. **In Node, every level is written to stderr,** because the agent reads the `yapparatus/agent` library's stdout as its prompt.
3. **The default level logs only warnings and errors.** The code logs requests, updates sent to the browser, and reply checks at `debug`. It logs changes to the chat and to diagnostics at `info`. When a snippet fails, the agent reads the snippet's stderr, so the library logs nothing at the default level.
