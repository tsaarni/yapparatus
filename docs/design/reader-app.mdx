# The reader app

The reader app is the code in the browser that shows a document. This page describes the screen, how the reader adds parts of a page to a message, and how the reader finds those parts again. [Rendering](rendering) describes how a page is compiled, and [the chat](chat) describes what happens to a message.

## The screen

The screen has a header, a sidebar, the page, and the chat panel.

1. **The header is at the top of the screen.** It shows the document title, the current chapter, and the Ask button. It also shows the number of errors and warnings when there are any, and the theme button when `document.json` allows a choice of theme.
2. **`document.json` can set a subtitle, a logo, and a favicon.** The subtitle is shown in small type above the title. The logo is shown beside the title and is as tall as the title and subtitle together. The logo and the favicon are icon names, such as the names in `<Icon>`.
3. **The sidebar lists the chapters.** Under the current chapter, it lists the sections and marks the section that the reader is in. The sidebar is 272 px wide.
4. **The sidebar becomes a drawer when the space beside the chat is less than 1100 px wide.** The drawer lists the same chapters and sections in the same order.
5. **The page and the chat scroll separately.** The window itself does not scroll. Each scrollbar is drawn at the right edge of its own area, so the two scrollbars do not overlap. When the page opens or the reader clicks it, the page takes the keyboard focus, so keys such as Page Down scroll it. Print shows the whole page.

## Asking about the page

The reader asks about a part of the page by adding it to a message as a context item. The message box shows each context item as a pill. See [what context is](addresses-and-context#what-context-is). <Ref to="selection-capture" /> shows how a selection becomes context items.

1. **Sections, figures, tables, listings, and code blocks have Link and Ask buttons.** The buttons appear when the pointer is over the element or the keyboard focus is in it. Link copies the address of the element. Ask adds the element to the message as a context item.
2. **Selected text opens the selection menu.** The menu has Ask and Copy link. Ask adds the selection to the message. Copy link copies the address of the selection; see [links, checks, and builds](addresses-and-context#links-checks-and-builds). A build has no chat, so its menu has only Copy link.
3. **A selection becomes one `text` context item for each block that it touches.** A block is a paragraph, a list item, a table row, or a line of code. The page compiler marks each block with its file and lines; see [compiling a page](rendering#compiling-a-page). The address of the item is the figure, table, listing, or section that holds the words, followed by the words as a text fragment.
4. **A selection in an external file becomes a `lines` context item.** Its address is the file address with the selected lines. When the selection covers only part of a line, the address also contains the selected words.
5. **A section item covers the section** from its heading to the next heading of the same or a higher level.
6. **A diagram item records the open step,** such as "Step 2 of 5 (miss): …". See [steps](diagrams#steps).

## Show on page

Each pill in a sent message has a Show on page button. The button scrolls to the part of the page that the context item names. The agent may have edited the page since the reader sent the message, so the button finds the part by its address and words. <Ref to="show-on-page-flow" /> shows the steps.

<Diagram id="show-on-page-flow" caption="How Show on page decides what to show. If there is not exactly one match, it shows the item's section or figure, or says that the target is gone." description="Decision flow for finding an earlier context item on the page" draw={(d) => {
  const start = d.start("Show on page clicked")
  const samePage = d.decision("Page open?", { id: "same-page" })
  const open = d.box("Open that page", { id: "open-page", sub: "then continue" })
  const byAddress = d.box("Find by address", { id: "find-by-address", sub: "id, then words" })
  const one = d.decision("One match?", { id: "one-match" })
  const show = d.box("Scroll and frame it", { id: "show-it", role: "accent" })
  const anchored = d.decision("Anchor there?", { id: "anchor-there" })
  const around = d.box("Show its anchor", { id: "show-anchor", sub: "say it changed" })
  const gone = d.box("Say it is gone", { id: "say-gone", sub: "or unclear", role: "warning" })
  d.equalSize([open, byAddress, show, around, gone])
  const main = d.column([start, samePage, byAddress, one, show], { gap: 40 })
  d.place(open, { rightOf: samePage, gap: 88 })
  d.place(anchored, { rightOf: one, gap: 88 })
  d.place(around, { below: anchored, gap: 40 })
  d.place(gone, { rightOf: anchored, gap: 88 })

  d.arrow(samePage, byAddress, { label: { text: "yes", side: "left" } })
  d.arrow(samePage, open, { label: "no" })
  d.arrow(open.bottom, byAddress.right, { id: "after-open", route: "vh", dashed: true })
  d.arrow(byAddress, one)
  d.arrow(one, show, { label: { text: "yes", side: "left" } })
  d.arrow(one, anchored, { label: "no" })
  d.arrow(anchored, around, { label: { text: "yes", side: "left" } })
  d.arrow(anchored, gone, { label: "no" })
}}>
  <Step focus="show-on-page-clicked same-page open-page after-open">Show on page first makes sure that the item's page is open.</Step>
  <Step focus="find-by-address">It finds the target by the item's address. A section, figure, table, or listing is the element with the address's id, and a diagram part is the part with its id in that figure. Text and code have no id of their own. For these, the targets are the blocks of the page that hold the selected words, or its code blocks. When there are several, it keeps the one at the item's lines.</Step>
  <Step focus="one-match show-it">If there is exactly one match, it scrolls to the target and frames it.</Step>
  <Step focus="anchor-there show-anchor">If there are no matches or several, it looks for the item's anchor: the figure, table, listing, or section around the selected words, or the figure around a part. It scrolls to the anchor and says that the target changed.</Step>
  <Step focus="say-gone">If the anchor is also gone, it says that the target disappeared or is unclear.</Step>
</Diagram>

1. **Show on page finds the target by its address.** It looks for the id first, and then for the selected words. When the words are in several places, it uses the lines of the item.
2. **Show on page highlights the target only when it finds exactly one match.** In other cases, it scrolls to the section or diagram around the target and says that the target changed. The agent often rewrites the target in its answer, so the surrounding section is the best place to look.
3. **Show on page opens an external file at the lines of the item.**
4. **An author gives an explicit `id` to a diagram part that prose refers to.** A derived id changes when the label changes, and Show on page then cannot find the part.

## The file view

The file view shows a whole external file; see [external files](rendering#external-files).

1. **Clicking a line number selects that line,** and shift-clicking extends the selection to a range, as on GitHub. The address then ends in a range such as `#L11-L14`.
2. **Clicking a line number in an excerpt opens the file view at that line.**
