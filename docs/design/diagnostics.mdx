# Diagnostics

Diagnostics are the errors and warnings in a document. Examples are a page that does not compile, a broken link, a diagram whose boxes overlap, and a page or reply that fails to render. The agent uses diagnostics more than the reader does, because the agent edits the pages and can fix the problems. This page describes where diagnostics come from, how they are identified, and who sees them.

## Where diagnostics come from

1. **The server checks everything that it can find from the source files.** Whenever a file changes, the server compiles every page and checks links, references, and `document.json`. Compiling also checks the Markdown conventions: code block languages, heading depth, alert kinds, and file trees. None of these checks need a browser.
2. **The browser checks what can be found only when a page runs.** These checks cover diagram layout, chart marks, render errors, runtime errors, and replies that fail to show. Text in diagrams and charts is measured with the page font, so these checks cannot run on the server. A chart reports under the diagram scope of its figure, `diagram:<file>#<figure>`, because charts and diagrams are both figures drawn in the browser.
3. **Each check has its own scope and always sends its complete set of diagnostics.** A scope is a name for the diagnostics of one check, such as `diagram:<file>#<figure>`. The browser sends the set with `PUT /-/api/diagnostics/{scope}`. An empty set clears the scope, so no separate delete request is needed.
4. **Runtime errors are reported per browser tab.** Each tab reports its runtime errors under its own scope. The tab clears them when a hot update starts, because the update replaces the code that failed. The tab removes them when it closes. If the new code throws the error again, the tab reports it again.
5. **A report that belongs to one revision of a file expires when the file changes.** A diagnostic from an old version therefore disappears when the fix is saved.
6. **Each page has a check state.** A browser that renders a page reports the page, even when it has no errors. A page that has changed since it was last rendered is listed as not checked. An empty list therefore always means that the checked pages have no problems.
7. **Direction:** an open tab also renders, off screen, the pages that it does not show, so that one tab checks the whole document. Browsers slow down background tabs, so this needs testing first.

## How diagnostics are identified

**An error is identified by its code, file, target, and subject.** The subject is what the error is about, such as a link's target or a diagram's parts. With this identity, an error whose message is reworded is still the same error, and two broken links on one page are two separate errors. When an error has no subject, its message identifies it.

## Who sees diagnostics

1. **The agent learns about new errors without asking.** The agent channel numbers its messages in a sequence. An error gets a number in this sequence after it has existed for 2 s. Errors with a number after the agent's cursor, its position in the sequence, are new. New errors end a `wait` in the same way as a reader message does. The prompt then lists all diagnostics with the new errors marked, and also the pages that are not checked. See [waiting](chat#waiting).
2. **The server refuses a reply while new errors remain.** The agent has no `wait` open while it edits. Errors caused by its own edits therefore reach the agent when it replies; see [replying](chat#replying).
3. **Short-lived errors and warnings never end the agent's wait.** An error that disappears within 2 s, such as one caused by a file that was saved half-written, gets no number. Warnings do not end a wait, so the agent does not spend a turn on them.
4. **The reader sees diagnostics in place and in a list.** A page that fails shows its error. A diagram or chart shows its diagnostics under the figure. When there are errors or warnings, the header shows how many there are. Each item in the list opens the place it is about. **Ask** attaches that place to the message box. A diagnostic therefore reaches the chat only when the reader asks about it.
