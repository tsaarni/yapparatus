# Styling

This page explains how the web app, its components, and its figures are styled: the tokens that hold every style value, the colors and themes built from them, and the rules that `pnpm verify` enforces.

## Overview

The web app is styled with [StyleX](https://stylexjs.com/), which compiles the styles of each component to atomic CSS at build time, so the style sheet grows only with the number of distinct values. Each component keeps its styles in its own file, next to its markup. Every value that a style uses, such as a color, a space, or a duration, is a token: a named, typed value defined once in [the theme file](/-/files/yapparatus/src/web/theme.stylex.ts). <Ref to="styling-files" /> shows where the styles are.

## Tokens

The colors, shadows, and font stacks change with the theme, so they are CSS variables. The scales, such as font sizes and spaces, are the same in every theme, so StyleX writes their values into each rule. Each color has a value for the screen, a light value for print, and a stronger value for increased contrast, which <Ref to="styling-role" /> combines into one.

The narrow condition is a container query on the reading column, which narrows both when the window shrinks and when the reader widens the chat. The chat panel uses a media query, because on a phone it covers the window. See [page layout](/web-app#page-layout).

The server draws [pictures](/diagram-compiler#pictures) in Node, where StyleX does not run, so it reads the theme file as plain values. Pictures, tests, and the web app then use the same colors.

A new value goes into a scale in the theme file, with a comment on what it is for. A new color role needs a dark and a light value and a contrast rule in the test.

## Color

A component asks for a color by its role, such as `textMuted`, and contains no color values. Each theme gives every role a value, so a new theme changes no component. <Ref to="styling-roles" /> shows the main roles in the current theme.

<Table id="styling-roles" caption="Color roles, shown in the current theme.">

| Role | Sample | Used for |
|---|---|---|
| `text` | <Swatch role="text" /> | Headings, emphasis |
| `textBody` | <Swatch role="textBody" /> | Reading text, plain code |
| `textMuted` | <Swatch role="textMuted" /> | Captions, labels, comments in code |
| `accent` | <Swatch role="accent" /> | Focus marks, the current position, accent elements in diagrams |
| `accentStrong` | <Swatch role="accentStrong" /> | Links, focus rings |
| `borderControl` | <Swatch role="borderControl" /> | Control edges, diagram outlines and lines |
| `error` | <Swatch role="error" /> | Errors |
| `warning` | <Swatch role="warning" /> | Warnings, warning elements in diagrams |
| `success` | <Swatch role="success" /> | Success, added lines |
| `category1`–`category4` | <Swatch role="category1" /> <Swatch role="category2" /> <Swatch role="category3" /> <Swatch role="category4" /> | Diagram and chart categories, in order |

</Table>

Each hue has one meaning. The indigo accent marks links, focus, the current position, and the primary action. Red is an error, amber a warning, and green success. The four category hues go, in order, to the [categories](/components#roles-and-categories) of a diagram or chart, and the first two stay apart with red-green color blindness. Color always comes with a second signal, such as an icon, text, or a shape.

Surfaces step away from the background in lightness: `canvas`, `surface`, `surfaceRaised`, and `surfaceHover`. Each is lighter than the one behind it in the dark theme and darker in the light theme. Only menus, notices, and panels over the page cast a shadow.

## Contrast

[The theme test](/-/files/yapparatus/tests/theme.test.ts) computes the WCAG contrast of each pair of roles drawn together, in the dark and light themes, each with increased contrast and in print. Text and status colors need 4.5:1, the [AA minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Control edges and diagram outlines need 3:1, the [minimum for graphics](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). Tinted fills and dividers need 1.3:1. The test also checks that the category colors stay apart with red-green color blindness.

<Ref to="styling-contrast" /> lists the ratios on `surface`, computed with the test's formula, and <Ref to="styling-contrast-chart" /> draws them. The smallest margin is `textMuted` on a tinted surface, at 4.82:1.

## Themes

The `"theme"` setting in `document.json` is `"dark"`, the default, `"light"`, or `"auto"`. With `"auto"`, the theme follows the system, and a header button switches between System, Light, and Dark and remembers the choice. The theme is applied before the first render, and the HTML page already names the color scheme, so the page does not change once it shows.

## Typography and scales

Inter is the font of text, the interface, and diagrams, and JetBrains Mono the font of code. Size, weight, and color show the hierarchy, with six font sizes and three weights. The page title scales with the reading column. The other scales hold spaces, which are multiples of 4 px, radii, sizes, layers, strokes, and durations, so that components written apart line up.

Diagram labels are 13.5 px, outside the scale, because the diagram compiler [measures text](/diagram-compiler#text-measurement) at this size.

## Feedback

The web app shows feedback where the reader acted. A copy button confirms on itself. A notice closes after a few seconds, and an error stays until dismissed. Clearing the chat asks for confirmation beside its button, because browser dialogs block the page and ignore the theme.

## Accessibility and print

Keyboard focus shows a 2 px ring, which stays visible as an outline in forced-colors mode. Reduced motion makes every transition instant, with one rule in [the base style sheet](/-/files/yapparatus/src/web/styles.css). StyleX puts its own rules in cascade layers, so this rule wins over all of them.

Print uses the light theme, because browsers leave out backgrounds and a dark theme would print light text on white. The header, the contents, and the chat are hidden, every tab prints with its label, and a diagram prints with its steps as a numbered list.

## Style rules

`pnpm verify` runs [the style check](/-/files/yapparatus/scripts/check-styles.ts), which rejects two things that StyleX accepts. One is shorthand properties, such as `border`: StyleX silently drops a shorthand that holds a theme variable, so styles write longhands such as `borderWidth`. The other is literal colors, such as hex values.

Two more rules are kept by convention. A component that needs a class name, for tests and debugging, sets it with `styled("name", ...styles)`, because spreading StyleX's props after a `className` replaces it. Each element carries its own style: a figure does not style the elements inside it.

## Icons

Interface icons come from Lucide and take the color of the text around them. Icons in pages come from Iconify and the document's own collection; see [icons](/page-compiler#icons).
