# Addresses and context

This page describes how each part of a document is named, and what context a message carries. How a selection becomes context, and how Show on page finds it again, is described in [the reader app](reader-app).

## Addresses

An address names a part of the document: a page, something on a page, words in it, an external file, or lines in that file. Links, `Ref`, Copy link, and context items all use the same addresses, so there is one set of forms to learn and to check. <Ref to="address-forms" /> lists them, each with an example from this document. A name in angle brackets stands for a value, such as a page name or an id.

<Table id="address-forms" caption="The address forms, with examples.">

| Form | Names | Example |
|---|---|---|
| `/<page>` | A page | [`/chat`](/chat) |
| `/<page>#<id>` | A section, or a figure, table, or listing by its id | [`/chat#replying`](/chat#replying), [`/architecture#system-map`](/architecture#system-map) |
| `/<page>#<figure>--<part>` | A part of a diagram: the figure's id, then the part's id | [`/architecture#system-map--agent`](/architecture#system-map--agent) |
| `/<page>#<figure>--<step>` | A step of a diagram, in the same way | `/cache#cached-read--miss`, for a step with `id="miss"` |
| `/<page>#<id>:~:text=…` | Words in the section, figure, table, or listing with that id | [`/api#api-status-codes:~:text=another%20host`](/api#api-status-codes:~:text=another%20host) |
| `/-/files/<directory>/<path>` | An external file | [`/-/files/yapparatus/src/protocol.ts`](/-/files/yapparatus/src/protocol.ts) |
| `/-/files/<directory>/<path>#<lines>` | Lines of the file, written as in [lines](#lines) | [`/-/files/yapparatus/src/protocol.ts#L61`](/-/files/yapparatus/src/protocol.ts#L61), [`/-/files/yapparatus/src/protocol.ts#L54-L68`](/-/files/yapparatus/src/protocol.ts#L54-L68) |
| `/-/files/<directory>/<path>#<lines>:~:text=…` | Words in those lines | [`/-/files/yapparatus/src/protocol.ts#L61:~:text=address`](/-/files/yapparatus/src/protocol.ts#L61:~:text=address) |

</Table>

1. **Pages are at the root, and everything else is under `/-/`.** `/chat` is a page, `/-/files/yapparatus/src/protocol.ts` is a file view, and `/-/api/chat` is the API. A page name cannot start with `-`, so the two never collide.
2. **Ids come from headings and `id` attributes.** The heading "Text fragments" gets `#text-fragments`, and `<Table id="address-forms">` gets `#address-forms`. A heading id is unique on its page. A figure, table, or listing id is unique in the document, so `<Ref to="address-forms" />` works from any page.
3. **Text is named by its words, inside the nearest id.** A table row, a tab panel, or a line of code has no id of its own: `/api#api-status-codes:~:text=another%20host`. An id per row would be one more thing to write. A position would change when a row is added. See [text fragments](#text-fragments).
4. **Drawn parts have ids, joined with `--`.** A reader cannot select a shape or an arrow as text, so a diagram part has an id: `/architecture#system-map--agent`. It is unique only in its figure. **[Direction](directions):** a chart part is named by its data values, as in `/charts#throughput-chart--Build=After`; see [charts](charts#where-the-data-comes-from).
5. **`<directory>` is a name from `document.json`,** so a file address does not depend on where the directory is on disk.

### Text fragments

Words are named with a text fragment, the part of an address after `:~:`. The format is the one in the [URL Fragment Text Directives](https://wicg.github.io/scroll-to-text-fragment/) specification, which browsers follow when they open a link: `text=[prefix-,]textStart[,textEnd][,-suffix]`.

1. **`textStart` alone names the words themselves.** A selection of up to eight words is written whole. Selecting "names another host" in <Ref to="/api#api-status-codes" /> gives `/api#api-status-codes:~:text=names%20another%20host`.
2. **`textStart,textEnd` names everything from the first words to the last.** A longer selection is written as its first four words and its last four, so the address stays short. Selecting the first paragraph of [the chat section](/api#chat) on the API page gives `/api#chat:~:text=The%20chat%20is%20a,the%20agent%20uses%20it.`, where the comma separates the start from the end.
3. **The words are percent-encoded,** and so are `-`, `,`, and `&`, which the format uses as separators.
4. **A browser that opens the address searches the whole page for the words.** It goes to the first place where they occur. Show on page searches only the blocks of the item's page that hold the words. Among several blocks, it keeps the one at the item's lines.
5. **[Direction](directions):** a selection whose words occur more than once on the page gets `prefix-` and `-suffix`, the words just before and after it, so that the address names one place. For example, "the chat" occurs many times on the API page, and `/api#chat:~:text=The-,chat,-is%20a%20log` names one of them. `prefix-` ends with a hyphen and `-suffix` starts with one. Every part that reads a text fragment, from Show on page to the prompt, reads all four parts.

### Lines

1. **Lines are written as on GitHub:** `#L40` for one line and `#L40-L72` for a range. **[Direction](directions):** a list, such as `#L40-L72,L80`.
2. **Lines come first and words second:** [`/-/files/yapparatus/src/protocol.ts#L61:~:text=address`](/-/files/yapparatus/src/protocol.ts#L61:~:text=address). The lines say where to look, and the words say which part of those lines the reader meant.

## Links, checks, and builds

1. **Links are checked.** A link or `Ref` that points to nothing, including a missing file or line, is an error in [diagnostics](diagnostics).
2. **Links work in every build.** The website build writes `architecture/index.html`, so any static host serves `/architecture#system-map`. The single HTML file has no server, so the same link becomes `#/architecture#system-map`.
3. **Copy link copies the address of the selection,** such as `/api#chat:~:text=log` or `/-/files/yapparatus/src/protocol.ts#L54-L68`. The single HTML file build leaves out the words and copies `#/api#chat`, because a browser does not look for words in an address that is already after `#`. **[Direction](directions):** the single file writes words with `~text=`, which browsers ignore, and the reader app finds the words itself, as Show on page does:

    | | Website | Single HTML file |
    |---|---|---|
    | Page | `/api#chat` | `#/api#chat` |
    | Words | `/api#chat:~:text=log` | `#/api#chat~text=log` |


## What context is

Context is what the reader attaches to a message. Each attached thing is a context item, shown as a pill above the message box. The message and its context form the prompt. Anything that has an [address](#addresses) can be attached.

1. **No context means the whole document.** The page that the reader is on is context only when the reader adds it.
2. **A context item is an address.** The agent reads the text from the file at that address.
3. **The prompt names blocks by their ids.** A pill shows "Figure 3.1", and the prompt has `#system-map`. Numbers change when a figure is added, and ids stay the same.
