# Addresses and context

This page describes how each part of a document is named, how a reader's selection becomes context for a question, and how that context is found again after the page changes. What happens to the question after that is described in [the chat](chat).

## Addresses

1. **One address form:** `/page#id`. For selected words, a text fragment is added: `/page#id:~:text=…`. A text fragment is the part of an address after `:~:text=`, which names words on the page. Ids are heading slugs, the `id`s of numbered blocks, and diagram parts written as `figure--part`. A heading slug is the heading text, lowercased, with hyphens between the words. Links, `Ref`, Copy link, and context items all use this form, so there is only one form to learn and to check.
2. **Ids are unique per page, and `--` is reserved for diagram parts and steps.**
3. **Page addresses start at the root, and the application's own addresses start with `/-/`.** This keeps page addresses short. No page name is reserved, because a page name cannot start with `-`. GitLab moved its routes under `/-/` for the same reason.
4. **An external file's address is `/-/files/<directory>/<path>`,** with lines written as on GitHub: `#L40` or `#L40-L72`. `<directory>` is the name that `document.json` gives to a directory under `"files"`. Addresses therefore stay the same wherever the directory is on disk. Selected words are added after the lines as a text fragment, `#L41:~:text=retry`, in the same way as on pages.
5. **Links are checked.** A link, anchor, or `Ref` that points to nothing is reported with its file and line. A link to an external file must name a file that the server can show, and lines that exist in that file. A broken link is therefore found before a reader follows it. See [diagnostics](diagnostics).
6. **Links work in every build.** The website build writes one file per address. The single HTML file uses addresses of the form `#/page#anchor`.
7. **Copy link on a selection adds a text fragment** (`#section:~:text=…`), because the selected words are what the reader means. Browsers scroll to the words in a text fragment and highlight them. In an external file, Copy link copies the file's address with the selected lines. When the selection covers only part of those lines, Copy link also adds the selected words. The single HTML file copies the section's address.

## What context is

Context is what the reader attaches to a message. Each attached item is shown as a pill above the message box. The agent reads the context to learn what a question is about.

1. **Context is only what the reader attached.** Readers can add prose, code, diagram parts, sections, figures, and whole pages, in any combination. The page that the reader is on is not context unless the reader adds it. As a result, the message contains nothing that the reader did not see attached.
2. **No context means a question about the whole document,** and the prompt says so. The agent must not guess a scope that the reader did not give.
3. **A context item is an address and the location of its source,** and nothing more. No text is copied from the file, because the agent has the files and only needs to know where to look. <Ref to="context-item" /> shows the type.
4. **A page item or a file item names the whole file,** with no lines in the prompt. The Ask about this button on a page title, or on the title of the file view, adds such an item. The agent then reads the file.
5. **Generated numbers are not addresses.** A pill shows the reader a number such as "Section 5.2.2" or "Figure 3.1", which is computed when the pill is shown. The agent sees only what the source contains: files, lines, heading slugs, and ids that the author wrote. Numbers are not in the source, and they change when a figure is inserted. Also, "section 2" typed in a message could mean several things.

1. **The compiler records the source location in the page, and the browser sends it back.** An MDX plugin marks each top-level block, list item, and table row with its file, lines, and hash. Authors therefore do not need to give paragraphs ids. A selection in one list item points to the line of that item only, and not to the whole list.
2. **A selection becomes one text item for each range it touches.** A range is the innermost marked block, list item, or table row. The address of each item is the nearest section's address with the selected words as a text fragment. This is the same fragment that Copy link makes.
3. **Code from an external file is context about the file.** A selection in an excerpt or in the file view becomes a `lines` item. The item contains the file's address with the selected lines, the file's path relative to the project directory, and the hash of the lines. When the selection covers only part of its lines, the address keeps the selected words as a text fragment, and the prompt quotes them. This is needed because the lines alone do not show which name on a line the reader means. The server accepts such an item only for a file that the document shows, and only when the item's path and lines agree with its address.
4. **Line numbers select lines, as on GitHub.** In the file view, clicking a line number selects that line, and shift-clicking extends the range. The address then ends in `#L11-L14`. The selected lines become the text selection, so the menu offers the same Ask and Copy link actions as for any other selection. Clicking a line number in an excerpt opens the file at that line.
5. **A figure item records the open step,** for example "Step 2 of 5 (miss): …". The agent then knows what the reader was looking at. See [steps](diagrams#steps).

## Finding the lines again

The reader can send a message while the agent is editing. Lines that were correct when the message was sent may therefore be wrong when the agent reads it. Both the server and the browser find the lines again by their hash. The server does this when it writes the prompt. The browser does this when the reader clicks Show on page, which is the button on a pill in a sent message. <Ref to="show-on-page-flow" /> shows how Show on page decides what to show.

  <Step focus="show-on-page-clicked same-page open-page after-open">Show on page first makes sure that the item's page is open.</Step>
  <Step focus="same-hash">It collects the ranges that have the item's file and hash. Then it narrows them by the words in the address, the part id, or the kind.</Step>

1. **Each range has its own hash.** The agent edits pages often. With one hash per file, every edit would invalidate every open selection on the page.
2. **The server locates each item again when it writes the prompt.** If the hash still matches at the same lines, the server prints those lines. Otherwise, it prints the single run of lines in the file that has that hash. If no lines have that hash, it prints "changed since asked" with the old lines. A section runs from its heading to the next heading of the same level.
3. **Show on page highlights a target only when it is sure of the location.** Highlighting the wrong place would mislead the reader more than highlighting nothing. When the exact target is gone, Show on page uses the target's anchor instead, because the anchor's location is still certain. The anchor is the section around the selected words, or the figure around a diagram part. The target is usually gone because the agent rewrote it in its answer, so the target's section is the place to look. Approximate matching of the old words, which annotation tools use, is left out. An agent usually rewrites more than a few words, and an approximate match could frame the wrong place.
4. **An edited block no longer locates older items that point into it.** Items in other blocks keep working.
5. **Show on page opens an external file at the item's lines** and checks their hash against the code shown. If the file has changed, it goes to the single run of lines with that hash, as the server does. If there is no such run, it says that the lines changed.
6. **Diagram parts are matched by id.** The id is derived from the label unless the author gives one. Prose that refers to a part should give the part an explicit `id`, so that editing the label does not break the reference.
