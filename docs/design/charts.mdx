# Charts

A chart is a figure that [Observable Plot](https://observablehq.com/plot/), a JavaScript charting library, draws from data. This page follows a chart's data from the page or a file to the drawing.

## Overview

The [page compiler](page-compiler#charts) reads the data, gives each column a type, runs the chart's `plot` function on it, and draws the chart, so problems with the data, the marks, and the drawing are reported without a browser. The browser runs `plot` again and draws the chart the same way at the width of the page. <Ref to="charts-path" /> shows the path.

The page compiler reads the CSV and TSV formats, gives the columns their types, and checks them, the calls to Plot, and the drawing. The browser waits for the fonts and draws the chart. Both sides draw with one function, so the typed data and the drawing are the same on both.

## Data sources

A chart has one source of data. Without `from`, it holds a fenced `csv` or `tsv` block, which is not shown. `from="#id"` names a `<Table>` on the same page, and a file address names a `.csv` or `.tsv` file, read by the [external file](documents#external-files) rules. Data from a block or a table goes into the page. A file's data stays out of it, and the chart gets a function that loads it. Two sources, or a `from` that names no table, are `CHART_DATA`, and a missing `plot` is `CHART_PLOT`.

## Column types and checks

Each source gives a header and rows of cell text, each row with its line. The cells are then checked:

1. Each column name must be present and unique, because `plot` names fields by it.
2. Each row must have as many cells as the header.
3. Each column is a number column when every cell is a plain number, a date column when every cell is an ISO date such as `2026-01-31`, and text otherwise. Empty cells do not count.
4. A column that mixes types is reported at the first cell that differs from most cells.

Each problem is `CHART_DATA`. The typed data, `ChartData`, holds the columns, each with its name as written in the header and its type, and one array of cells per column, in column order. An empty cell is `null` and a date is ISO text, so the data is plain JSON. The chart turns it into one object per row before it calls `plot`, with each date as a `Date`.

## The data module

A file's data is its own module, named with a hash of the file's text, so a browser never uses an old copy. An edit to the file compiles the page again and changes its [revision](page-compiler#revisions). The chart loads the data when it comes near the screen, and before printing. In dev mode every chart loads its data after a short delay, so the browser checks every chart.

## Drawing

The browser and the page compiler draw a chart with one function. It takes Plot, what `plot` returned, the rows, the width, a document to make the elements in, the font with a text measure, and the colors. The browser passes its own document, its fonts measured by the browser, and the theme's colors as CSS variables. The page compiler passes a document without a browser, from [linkedom](https://github.com/WebReflection/linkedom), the font measure of the [diagram compiler](diagram-compiler), and the light theme's colors. The chart draws twice:

1. The first drawing gives the categories and the box of every label. Each margin grows by how far a label reaches past the edge, and by how far an axis label crowds the tick labels on its side of the plot. Plot keeps an axis label at the edge of the figure, so a wider margin moves the tick labels away from it.
2. The second drawing uses the categories in their order and the new margins. Labels that still run into each other are `CHART_OVERLAP`.

Neither side reads the layout of a drawing. The box of a label comes from its attributes: its position and the transforms around it, its anchor, its lines, its font size, and the width of its text from the measure, with the font's ascent and descent for its height. A rotated label keeps its rotated box, so rotated tick labels overlap only when their text does. The boxes agree with Chrome's within about a pixel.

Plot writes its warnings, such as dates on a band scale, to the console and puts a warning sign in the figure. The chart takes the sign out and reports each warning as `CHART_WARNING`, with what the author can do.

The browser waits for the web app's fonts, because labels measured with a fallback font would be wrong, and draws again when its width changes. It shows the second drawing with a legend.

The page compiler draws each chart at the widest width a chart has in the reading layout, and again at the width it has on a phone. Overlap depends on the width, so a reader at another width can still see labels overlap. An overlap that only the phone width has names that width. It does not draw a chart whose data or marks have errors, since those are reported already.

## Color

A chart's `fill` or `stroke` names the column of categories. The colors are the four category colors of [the theme](styling#color), as CSS variables, so a theme switch needs no new drawing. Categories take the colors in the order the rows first use them, as diagram categories do. A fifth category and later ones are muted and reported as `TOO_MANY_CATEGORIES`, a warning.

**[Direction](directions):** a user can point at a dot, a line, or a range of a chart. The address names it by its data values, such as `/sales#sales-chart--Month=2026-03` or `Revenue=100..300`, so it still finds the marks after rows are added or sorted.

## Checks on the marks

The library that `plot` receives checks each call before it calls Plot. The page compiler runs `plot` with this library in a fresh JavaScript context with a time limit of 1 second, as it runs a diagram's draw program, so `plot` uses only `Plot`, `rows`, and the values it defines itself. The two drawings run within the same time limit, because Plot calls the accessors that `plot` wrote while it draws. A `plot` whose run and drawings pass the time limit is `CHART_PLOT`. <Ref to="charts-mark-checks" /> lists the checks and where each is found.

<Table id="charts-mark-checks" caption="The checks on what plot asks of Plot and on the drawing. All are errors except the last three, which are warnings.">

| Code | Found when | Found by |
|---|---|---|
| `CHART_FIELD` | A field, such as `x` or `fill`, names no column | Page compiler |
| `CHART_COLOR` | `fill` or `stroke` is a CSS color, such as `"tomato"` | Page compiler |
| `CHART_OPTION` | `plot` calls `Plot.plot` or `Plot.legend`, or returns more than `marks`, `x`, `y`, `fx`, `fy`, and `r` | Page compiler |
| `CHART_FAILED` | `plot` throws, or Plot throws while it draws | Page compiler |
| `CHART_OVERLAP` | Tick labels on one axis overlap, or an axis label overlaps tick labels | Page compiler |
| `CHART_WARNING` | Plot warns while it draws | Page compiler |
| `TOO_MANY_CATEGORIES` | The colors name more categories than the theme has colors | Page compiler |

</Table>

Plot alone draws nothing for an unknown field without an error, and reads a color name as a constant color. The page compiler finds every problem in the table when the page compiles, so the agent sees it before anyone opens the page. In dev mode, the browser shows the problems of its own drawing under the chart, and reports to the server only a data file that does not load, as [revisions and reports](diagnostics#revisions-and-reports) describes.

## Design decisions

**Charts use Observable Plot.** Agents already know Plot's marks.

**Data is written as data.** A table, a block, or a file can be checked at compile time with a line for each problem, and an array in `plot` cannot.

**Categories take colors in the order of first use.** Plot's default sorts the values, so one added row could change every color.

**A file's data is a separate module.** Rows in the page would make it slow to open and to compile.

**Label boxes come from attributes.** A server has no layout engine, and one computation for both sides finds each problem once, in the page compiler, with the same margins the reader sees.
