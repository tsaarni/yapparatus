# Charts

A chart is a figure that [Observable Plot](https://observablehq.com/plot/), a JavaScript charting library, draws from data. This page follows a chart's data from the page or a file to the drawing. Authors read [the chart reference](/-/files/yapparatus/starter/docs/charts.md).

## Overview

The [page compiler](page-compiler#charts) reads the data and gives each column a type, so data problems are reported at their lines without a browser. The browser runs the author's `plot` function and draws the chart at the width of the page. <Ref to="charts-path" /> shows the path.

## Data sources

A chart has one source of data. Without `from`, it holds a fenced `csv` or `tsv` block, which is not shown. `from="#id"` names a `<Table>` on the same page, and a file address names a `.csv` or `.tsv` file, read by the [external file](documents#external-files) rules. Data from a block or a table goes into the page. A file's data stays out of it, and the chart gets a function that loads it. Two sources, or a `from` that names no table, are `CHART_DATA`, and a missing `plot` is `CHART_PLOT`.

## Column types and checks

Each source gives a header and rows of cell text, each row with its line. The cells are then checked:

1. Each column name must be present and unique, because `plot` names fields by it.
2. Each row must have as many cells as the header.
3. Each column is a number column when every cell is a plain number, a date column when every cell is an ISO date such as `2026-01-31`, and text otherwise. Empty cells do not count.
4. A column that mixes types is reported at the first cell that differs from most cells.

Each problem is `CHART_DATA`. <Ref to="charts-data-type" /> shows the typed data: one array per column, with `null` for an empty cell and dates as text, so the data is plain JSON.

## The data module

A file's data is its own module, named with a hash of the file's text, so a browser never uses an old copy. An edit to the file compiles the page again and changes its [revision](page-compiler#revisions). The chart loads the data when it comes near the screen, and before printing. In dev mode every chart loads its data after a short delay, so the browser checks every chart.

## Drawing

The chart waits for the web app's fonts, because margins measured with a fallback font would be wrong, and draws again when its width changes. It calls `plot` with the rows and a [checked Plot library](#checks-on-the-marks), adds the width, the font, and the colors, and draws twice, off screen:

1. The first drawing gives the categories and the extent of every label. Each margin grows by how far a label reaches past the edge.
2. The second drawing uses the categories in their order and the new margins. Tick labels that still run into each other are `CHART_OVERLAP`.

The chart shows the second drawing with a legend.

## Color

The author names the column of categories with `fill` or `stroke`, and the chart sets the colors: the four category colors of [the theme](styling#color), as CSS variables, so a theme switch needs no new drawing. Categories take the colors in the order the rows first use them, as diagram categories do. A fifth category and later ones are muted and reported as `TOO_MANY_CATEGORIES`, a warning.

**[Direction](directions):** a reader can point at a dot, a line, or a range of a chart. The address names it by its data values, such as `/charts#charts-modules--Module=web%2Fchart%2Fchart.tsx` or `Lines=100..300`, so it still finds the marks after rows are added or sorted.

## Checks on the marks

The library that `plot` receives checks each call before it calls Plot. <Ref to="charts-mark-checks" /> lists the checks.

<Table id="charts-mark-checks" caption="The checks on what plot asks of Plot. All are errors except CHART_OVERLAP.">

| Code | Found when |
|---|---|
| `CHART_FIELD` | A field, such as `x` or `fill`, names no column |
| `CHART_COLOR` | `fill` or `stroke` is a CSS color, such as `"tomato"` |
| `CHART_OPTION` | `plot` calls `Plot.plot` or `Plot.legend`, or returns more than `marks`, `x`, `y`, `fx`, `fy`, and `r` |
| `CHART_FAILED` | `plot` or Plot throws |
| `CHART_OVERLAP` | Tick labels on one axis overlap |

</Table>

Plot alone draws nothing for an unknown field without an error, and reads a color name as a constant color. The chart reports its problems from the browser, as [revisions and reports](diagnostics#revisions-and-reports) describes, so they are known only after a browser has shown the page.

## Design decisions

**Charts use Observable Plot.** Agents already know Plot's marks.

**Data is written as data.** A table, a block, or a file can be checked at compile time with a line for each problem, and an array in `plot` cannot.

**Categories take colors in the order of first use.** Plot's default sorts the values, so one added row could change every color.

**A file's data is a separate module.** Rows in the page would make it slow to open and to compile.
