# Directions

This page lists ideas that are not built, and open questions. None of them is decided: each idea is designed in full, changed, or dropped when work on it starts. The page that an idea would change describes it under a **Direction** marker that links here. When an idea is added, built, or dropped, this list changes in the same edit.

## Ideas

- **Comments on repeated words.** When the selected words occur more than once on a page, the address also holds the words before and after them. The web app and the agent then find the place that the user selected. See [text fragments](documents#text-fragments).
- **Several line ranges in one comment.** A file address takes a list of lines, such as `#L54-L68,L80`. See [lines](documents#lines).
- **Selected words in single-file links.** In the single HTML file, Copy link keeps the selected words as `#/page#id~text=…`, and the web app finds them. See [addresses in builds](documents#addresses-in-builds).
- **Comments on chart marks.** A user can comment on a dot, a line, or a range of a chart. The address names the marks by their data values, such as `Month=2026-03`, so it stays correct after rows are added or sorted. See [color](charts#color) and [addresses](documents#addresses).
- **Images from the project's assets.** A page shows a screenshot or a photo from `assets/` with Markdown image syntax, as `assets:name.png`. The build bundles it, and `-light` and `-dark` files follow the theme. Diagrams and charts stay draw programs. See [icons](page-compiler#icons).
- **Pages rendered on the server.** The website build writes the content of each page into the page's HTML file, and the web app takes over that HTML in the browser. Readers without JavaScript, search engines, link previews, and agents that fetch a page as text then see its text, tables, code, and diagrams, and the page shows before its scripts load. In dev mode, the server renders every page after each change and reports the pages that throw, so the agent sees render errors without a browser. See [builds](page-compiler#builds) and [origins](diagnostics#origins).
- **Smaller builds.** The single file stores its script compressed, a build keeps only the glyphs of the characters it holds, and a build holds Observable Plot only when a page has a chart. The single file becomes about 70% smaller. See [builds](page-compiler#builds).
- **The user ends the agent's working state.** The chat panel shows when the server last heard from the agent, and a Disconnect button. The working state has no time limit. See [agent state](server#agent-state) and [chat panel](web-app#chat-panel).

### Diagrams

These ideas add to what a draw program can draw and to what its diagnostics say. Each one would be built when an author needs it for a document.

- **More of sequence diagrams.** A sequence also draws found and lost messages, which start or end at the edge of the diagram, messages that create or destroy a participant, and `ref` fragments, which refer to another sequence. See [sequences](diagram-compiler#sequences).
- **Stricter reply matching.** The compiler matches replies to calls more strictly. `REPLY_WITHOUT_CALL` and the activation bars use one matching, so the ends of the bars change too. See [sequences](diagram-compiler#sequences).
- **Arrowheads for class and ER diagrams.** The end of an edge can have a hollow triangle, a filled or hollow diamond, or a crow's foot. See [arrowheads](diagram-compiler#arrowheads).
- **Braces.** A brace is an edge style, as in `d.line(a, b, { style: "brace" })`. Labels, steps, and checks work on a brace as on every edge. See [edges](diagram-compiler#edges).
- **Swimlanes.** The diagram reference shows swimlanes as a grid with a title on each row. A call for swimlanes is added only when the pattern is not enough. See [the scene](diagram-compiler#the-scene).
- **The nearest call in an error.** When a draw program calls a function that does not exist, such as `d.cilinder(…)`, the message names the nearest call, `d.cylinder`. The agent then fixes the call in one step. See [the scene](diagram-compiler#the-scene).
- **Page lines in diagram diagnostics.** A diagnostic about an element names the page line of the call that created the element and of the call that placed it. The agent then finds the call to change. See [checks](diagram-compiler#checks).
