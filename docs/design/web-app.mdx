# Web app

The web app is the program in the browser that shows a document and its chat. This page describes the screen, how the web app moves between pages and follows edits, how it lays out and numbers a page, how the reader comments on the page, and how it shows the chat and the diagnostics. How each built-in component renders is on [components](components).

The window itself does not scroll, so each scrollbar is at the edge of its own region. The page takes the keyboard focus at startup and when the reader clicks it, so keys such as Page Down scroll it. Print shows only the page.

## Navigation

The router is the part of the web app that turns an [address](documents#addresses) into what the screen shows. It receives every navigation from the browser's Navigation API. <Ref to="web-navigation" /> follows one click on a link.

  const router = d.box("Router", { role: "accent" })
  const code = d.box("Page code", { id: "page-code" })
  const screen = d.box("Screen")
  d.sequence([reader, browser, router, code, screen], [

    { from: reader, to: browser, label: "click", id: "click" },
    { from: browser, to: router, label: "navigation", id: "event" },
    { from: router, to: browser, label: "save scroll", id: "save", async: true },
    { from: router, to: code, label: "wait for code", id: "await" },
    { from: code, to: router, label: "page code", reply: true, id: "loaded" },
    { from: router, to: screen, label: "new page", id: "route" },
    { fragment: "alt", title: "Back or Forward", id: "scroll", steps: [
      { from: screen, to: screen, label: "restore", id: "restore" },

    ] }] },

}}>
  <Step focus="reader router point prefetch">When the pointer or the keyboard focus reaches a link, the router starts loading the code of its page.</Step>
  <Step focus="browser click event">The browser changes the address at once. The router takes over if the address belongs to the document.</Step>
  <Step focus="save">The router saves the scroll position of the page the reader leaves.</Step>
  <Step focus="page-code await loaded">The old page stays on screen until the new page's code has loaded.</Step>
  <Step focus="screen route scroll">The new page renders. Back and Forward restore the saved position. Other navigations scroll to the target or to the top.</Step>
</Diagram>

The router leaves reloads, downloads, and other sites to the browser. It does the scrolling itself, because the browser restores only the window's position, and the page scrolls in its own region. Each page's code loads once and is kept, so a prefetch and a click share one load. When the reader follows another link while a page loads, the latest navigation wins.

While the reader reads, the web app also loads the next page in the contents. In a browser without the Navigation API, every link loads a page from the server, and links between pages of a [single-file build](page-compiler#builds) do not work.

## Hot updates

In dev mode, the web app shows an edited page without a reload. When a page or an external file that it excerpts changes, the page compiler compiles the page again, and the [document module](page-compiler#the-document-module) swaps in the new page and its outline. The web app then numbers the document again and renders the page with its new code. An edit to `document.json` reloads the web app.

The chat panel is outside the page, so an update keeps the reader's draft, references, and place in the chat. Session storage keeps them across a reload too.

Text stays in the text column. Code, tables, figures, file trees, tabs, and columns may grow into the breakout track as far as their content needs. When space is short, the breakout track shrinks first, then the text column. A diagram then scrolls sideways, and so do long code lines and wide tables.

Reading styles, such as the title size, change when the text column becomes narrow, which also happens when the reader widens the chat. See [typography and scales](styling#typography-and-scales).

## Numbering and references

The web app numbers the document from the outlines in the document module, so it needs no page's code. A chapter number is the page's position in `document.json`. Sections are numbered 3.2 and 3.2.1 within their chapter. Figures, tables, and listings each have their own counter per chapter, and only items with an `id` are numbered. `document.json` can turn numbering off; the label is then the caption or the heading.

The same pass collects every page, heading, figure, table, and listing that a `Ref` can point to. A `Ref` shows its target's current label, so it follows renumbering.

## Commenting on the page

In dev mode, the reader adds parts of the page to the next message as [references](documents#references), in three ways. Pages, sections, figures, tables, listings, and code blocks are targets. A target shows a Comment button, and a Link button that copies its address, when the pointer or the keyboard focus is on it. A diagram element is added by a click. Selected text opens a menu with Comment and Copy link, which copies the address of the words as a [text fragment](documents#text-fragments). Builds keep only the Link buttons and Copy link.

<Ref to="web-selection" /> shows how a selection that touches three blocks becomes three references.

A section reference runs from its heading to the next heading of the same or a higher level. An element's address is `figure--element`, and when the figure has a step open, the reference records the step and its text. Adding a reference opens the chat.

## Show on page

## File view

The file view shows a whole external file at its file address, `/-/files/<directory>/<path>`. In dev mode the web app reads the file from the server's [files resource](rest-api#read-an-external-file), and reads it again when the file changes. A build holds only the files that its pages name; see [builds](page-compiler#builds).

The view draws the file like an excerpt. The file is a target, and under its title, "Discussed in" lists the sections that link to it or excerpt it. Line numbers work as on GitHub: a click selects a line, a shift-click extends the selection, and the address ends in a range such as `#L11-L14`. A click on a line number in an excerpt opens the file view at that line.

## Chat panel

The chat panel exists only in dev mode. It shows the [chat](server#chat-log) in order, a typing indicator, and the message box. The server's [updates](rest-api#updates) keep it current.

A reader message shows its references, each with its address and the Show on page button. A reply is MDX that the server has compiled into a module. The web app loads the module and renders it with the same components as a page, without numbers or Comment buttons, and with ids prefixed so that they do not clash with the page's.

The panel header shows the [agent state](server#agent-state). While the newest message is unanswered and an agent is connected, the thread ends with typing dots and the seconds since the message. While no agent is connected, Copy prompt copies the [start prompt](agent-library#prompts) for a new agent. Clear deletes the chat on the server after the reader confirms. The thread follows new messages while the reader is at its bottom.

## Diagnostics display

In dev mode, the header shows the number of errors and warnings, and opens a list of them grouped by page. An item's code and line open the page at the diagnostic's place. Its message is text that the reader can select, and its Copy button copies the diagnostic with its file and line. Its Comment button writes a request to fix the diagnostic into the message box. Diagnostics also appear in place: a page that fails to render shows its error instead of its content, and a [diagram](components#diagram) or chart lists them under the figure.

Some problems appear only when a page runs in the browser: render errors, runtime errors, chart problems, and replies that fail to show. The web app reports them to the server with the page's revision, and reports a clean revision too, so the server knows the page was checked. See [revisions and reports](diagnostics#revisions-and-reports).

## Design decisions

The router uses the Navigation API because it reports every navigation through one event, including Back, Forward, and links in replies. The address changes before the page loads because Safari lacks the option to delay it.

Edited pages update in place because React's Fast Refresh reloads the whole app for a page module, which also exports its outline. A reload makes the page flash and loses the reader's place.
